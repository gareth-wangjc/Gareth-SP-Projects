# Progress Log — 2026-06-08
## H5 Locker Collection V2 — OTP Rate Limiting

---

### What was implemented

**Source spec:** `OTP_rate_limiting.md`
**File changed:** `H5 page for locker collection V2.html`

#### 1. Attempt tracking variables
Added to top of script block:
- `otpAttempts` — increments on each submission
- `OTP_MAX_ATTEMPTS = 30`
- `OTP_LOCKOUT_SECONDS = 300` (5 minutes)

#### 2. OTP submission logic
- `handleOTP()` now routes to `handleOTPSubmit()` instead of calling `otpSuccess()` directly
- `handleOTPSubmit()` increments the counter, triggers lockout if > 30, shows remaining-attempts warning if ≤ 5 left

#### 3. Lockout UI
Restructured `stepOTP` into two mutually exclusive containers:
- `#otpNormalContent` — OTP inputs, loader, attempts warning, resend line, back button
- `#otpLockout` — warning icon, "Too many attempts" copy, live 5:00 countdown

`showOTPLockout()` hides `otpNormalContent` and shows `otpLockout`. `resetOTPLockout()` reverses this when the timer hits 0.

#### 4. Demo tab
Added a 5th tab **"OTP LOCKOUT"** that skips straight to the lockout state on click — no need to submit 30 wrong attempts to demo the UI.

#### 5. `initApp()` reset
Resets `otpAttempts = 0` and restores normal content on every flow/tab switch.

---

### Product decisions made

| Topic | Decision | Rationale |
|---|---|---|
| Hide "Back to Phone Input" during lockout | **Yes — remove it** | User is physically at locker; no meaningful action they can take. Legitimate users won't hit 30 wrong attempts. |
| Hide "Resend in 24s" during lockout | **Yes — remove it** | Makes no sense to resend while locked out. |
| Counter scope | **Per session token** (BE spec) | Per-phone-number counter would allow bypass by switching numbers. Session token scope closes that gap. |
| BRD requirement to hide back button until timer = 0 | **Pushed back** | Frontend hiding adds no real security (user can close browser). Timer is the UX signal, not a navigation gate. |

---

### Notes for engineering handoff

- Frontend rate limiting is a UX guardrail only — backend must enforce the 30-attempt limit on the OTP verification endpoint tied to the session token
- On the 30th failed attempt, backend should invalidate the session token entirely (force re-scan)
- Return error code `OTP_MAX_ATTEMPTS_EXCEEDED` so frontend can trigger lockout state
- Lockout duration (5 min) and attempt ceiling (30) should be BE-configurable per market
