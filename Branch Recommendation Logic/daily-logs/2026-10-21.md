## Decisions made
- **Emap sorts by distance from the reference point.** A map list is read by location. Following SOP rank would make the map jump.
- **MPL passes only the reference point and the recommended branch ID.** No `rank_branches`, no full-list ranking, no timeout, QPS or fallback sizing.
- **Recommended tag only if MPL passes it AND on first load.** Removed after the buyer searches or moves the map.
- **First load order.** Last used on top if selectable. If not, the recommended branch is pinned at the top with the tag.
- **Control group gets nothing.** The emap behaves as it does today.
- **Order API stays** for unavailable used branches.
- **Reference point = last used branch is new.** Noted in the PRD.
- **No new sign-off date.** Earlier sign-offs stand unless a market objects.

## Key findings
- **SOP and emap can differ at the top.** When last used is unavailable, SOP Slot 1 is the nearest available used branch. The emap shows the recommended branch first.
- **The parity metric is gone.** The 4.0 metrics are now tag shown rate, recommended branch selection rate and search rate after first load.
